# RapidPulse Durban — Project Overview

## 1. Project Description

RapidPulse Durban is a mobile emergency response prototype designed to help people in Durban, KwaZulu-Natal, access emergency information, basic first-aid guidance, and community support resources. The project aims to improve access to emergency assistance by providing a simple platform where users can view safety information, record basic patient details, simulate emergency requests, and register their interest in becoming community responders.

## 2. Problem Statement

During emergencies, people may struggle to access immediate guidance, communicate important patient information, or identify available support while waiting for professional emergency services. RapidPulse Durban aims to address these challenges through a centralised mobile application that provides useful information and demonstrates how a community-based emergency response network could operate.

## 3. Project Objectives

- Provide users with accessible first-aid and emergency safety information.
- Create a patient registration interface for basic contact and medical information.
- Demonstrate an emergency request and response tracking process.
- Maintain a response history showing previous demo requests and their statuses.
- Allow interested community members to submit responder applications.
- Include a gender-based violence (GBV) panic button interface to highlight the need for specialised emergency support.
- Promote awareness of emergency preparedness and responsible community participation.

## 4. Main Features

**User registration and sign-in:** Provides patient registration and a demo sign-in interface.

**Emergency response dashboard:** Displays a simulated Durban response map, a standby team indicator, and an emergency request button.

**Response tracking:** Shows a simulated responder profile, estimated arrival time, response status, and emergency contact notification interface.

**First-aid guide:** Provides general safety information for situations such as severe bleeding and an unresponsive person.

**Response history:** Displays demo emergency requests, dates, locations, statuses, and optional reference numbers.

**Community responder registration:** Allows users to submit their contact details, area, responder team preference, training information, and availability.

**GBV support interface:** Demonstrates a panic button concept for people who may need urgent assistance.

## 5. Technology Stack

- **React Native:** Mobile application interface and components.
- **JavaScript:** Application logic, state management, and interactive features.
- **Expo:** Development and testing environment.
- **React Hooks (`useState`):** Management of screens, registration forms, simulated requests, and response history.
- **StyleSheet:** Layout, colours, typography, and visual styling.

## 6. Security and Privacy Considerations

The project recognises the importance of protecting patient information and ensuring responsible emergency response management. Future development should include secure authentication, encrypted communication, appropriate access controls, secure data storage, privacy protections, responder identity verification, and audit logs.

Medical information and location data should only be collected when necessary and handled with appropriate consent and safeguards. Emergency and GBV alerts must be connected to verified services and tested before being used in real situations.

## 7. Current Project Status

RapidPulse Durban is currently a **working prototype in development**. Its interface includes registration forms, a simulated emergency response workflow, first-aid guidance, responder applications, and response history.

The current prototype does not dispatch real emergency responders, send applications to a server, verify user accounts, share live locations, or deliver real emergency notifications. These capabilities require further development, backend integration, security testing, and collaboration with appropriate emergency service providers.

## 8. Future Development

Planned improvements include:

- Integrating a secure backend and database.
- Implementing real user authentication and account verification.
- Connecting to verified emergency response services.
- Enabling consent-based location sharing and live response tracking.
- Developing secure emergency contact and GBV alert functionality.
- Introducing responder verification, approval, and availability management.
- Conducting functional, security, privacy, and usability testing.

## 9. Expected Impact

RapidPulse Durban aims to demonstrate how mobile technology could support emergency preparedness, improve access to basic first-aid information, organise community responder participation, and provide clearer visibility of emergency request progress. With appropriate partnerships, secure infrastructure, and professional oversight, the project could develop into a practical tool supporting emergency response initiatives in Durban.
